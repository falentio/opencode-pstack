### Refactoring

**Own the contract. Change the structure, not the behavior.** Use this playbook for "refactor", "rename", "extract", "inline", "dedupe", "restructure", "move this module", and "tidy up this area". Distinguish it from [Feature](feature.md), which adds behavior, and [Bug fix](bug-fix.md), which corrects behavior.

A refactor that smuggles in a behavior change loses its safety net. If cleanup reveals a missing feature or a real bug, split it out and ship the structural change first against the pinned contract. A redesign is allowed, but name it and route it to [Feature](feature.md). Large or cross-cutting structural work belongs to [figure-it-out](../../figure-it-out/SKILL.md). This includes a migration across many call sites or a coordinated reshape of many subsystems. This playbook covers focused-to-medium changes.

1. Pin the behavior contract first. Run the [how skill](../../how/SKILL.md) over the affected subsystem to learn the contract. Then write a characterization test, snapshot, or equivalence harness that captures current behavior before any structure moves. The harness makes "refactor" a checkable claim per [principle-prove-it-works](../../principle-prove-it-works/SKILL.md). If the area has no coverage, write the pin before touching structure. Type check and lint are not a pin. **Complete when.** The affected subsystem's contract is recorded and a characterization test, snapshot, or equivalence harness passes before any structural edit.

2. Name the structure the code is missing per [principle-model-the-domain](../../principle-model-the-domain/SKILL.md). Choose a state machine over scattered booleans, a table or registry over spread-out branching, a typed model over repeated shape assumptions, or a reducer over ad hoc mutations. Keep boring code when the shape is already clear and local. Make the reshape delete branches or invalid states instead of adding indirection. **Complete when.** The missing structure is named, and the planned reshape deletes a branch or invalid state rather than adding indirection, or the current clear and local shape stays in place.

3. Name the target shape. State what the module layout, types, and call graph should be if built today per [principle-foundational-thinking](../../principle-foundational-thinking/SKILL.md) and [principle-redesign-from-first-principles](../../principle-redesign-from-first-principles/SKILL.md). If the target crosses a function boundary, run [architect](../../architect/SKILL.md) for parallel design exploration of the shape before the move. **Complete when.** The target module layout, types, and call graph are stated, and an architect result exists before the move whenever the target crosses a function boundary.

4. Subtract before you add. Delete dead weight, collapse one-caller wrappers, drop redundant validators, and remove orphan references before introducing the new shape per [principle-subtract-before-you-add](../../principle-subtract-before-you-add/SKILL.md). Ship the smallest change that reaches the target shape per [principle-laziness-protocol](../../principle-laziness-protocol/SKILL.md). Revert speculative cleanup that "might help" instead of leaving it in the refactor. **Complete when.** All present dead weight, one-caller wrappers, redundant validators, and orphan references have been removed before the new shape is added, and no speculative cleanup remains.

5. Move in small behavior-preserving steps. Keep the pin green after each step. For API reshapes, migrate every caller and delete the old API in the same wave per [principle-migrate-callers-then-delete-legacy-apis](../../principle-migrate-callers-then-delete-legacy-apis/SKILL.md). No compatibility shims and no parallel old-and-new paths. Spot-check every rename against the actual files. Check strings, prose, and back-references because renames can silently miss them. Delegate the mechanical edits to a subagent on the inherited parent model with a specific scope. Give it the file paths, the names being moved, and the behavior to hold. Omit `Task.model`. Review the diff yourself. **Complete when.** Every move has a green pin, every API caller uses the new API and the old API is deleted when an API reshape applies, every rename was checked against actual files including strings, prose, and back-references, and the diff has been reviewed by you.

6. Prove behavior is unchanged on the real artifact, not "it compiles", per [principle-prove-it-works](../../principle-prove-it-works/SKILL.md). For larger reshapes, run an equivalence check. Use a script that diffs old-vs-new outputs, replay a recorded baseline against the new code, or use the relevant control skill for a smoke run on the matching surface. Own the verification. Do not trust a delegate's "looks good" summary. **Complete when.** Direct verification evidence from the real artifact exists, and every larger reshape has one completed equivalence check from the listed methods.

7. Confirm the change earns its place. Measure success by reduced reader load per [principle-minimize-reader-load](../../principle-minimize-reader-load/SKILL.md). Look for fewer layers between the question and the answer, less hidden state, and fewer indirections without a second consumer. Revert the structural diff if it does not lower reader load somewhere. **Complete when.** You can point to a concrete reduction in layers, hidden state, or one-consumer indirection, or the structural diff has been reverted.

8. Rebase into small ordered commits that tell the story. Use a subtraction commit, then the reshape, then any follow-on cleanup, so a single revert undoes one slice. Shape the commits with [principle-sequence-verifiable-units](../../principle-sequence-verifiable-units/SKILL.md) so each behavior-preserving slice stays green before the next. Run [Opening a PR](opening-a-pr.md). **Complete when.** The subtraction and reshape commits are ordered, any follow-on cleanup follows them, each slice is green before the next, and the Opening a PR playbook has run.

**Reply.** State the structure that changed. State the pin you held it against. State the equivalence proof. State the reader-load delta. State what shipped and what got reverted. State that no new behavior shipped.
